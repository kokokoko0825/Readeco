# 新刊ページ: 著者検索を発売日順の書籍検索APIに変更

## 背景
発売前は「予約販売中」に表示されていた新刊 A が、発売後に「発売中」に表示されなくなった。

旧実装の `searchBooksByAuthor` は次の手順で著者の本を集めていた。

1. `BooksTotal/Search` のキーワード検索で、著者名を `keyword` として検索
2. `sort: "standard"`（標準順）の上位30件を取得
3. 著者名が完全一致する本だけに絞り込む

この手順には2つの弱点がある。

- **順位**: 標準順は売上などで日々入れ替わる。発売後に旧作や文庫版が上位に来ると、新刊が30件から押し出される。
- **表記**: 「東野圭吾」と「東野 圭吾」のようにスペースの有無が違うだけで、完全一致の判定から落ちる。

## 変更内容（`utils/rakuten-api.ts`）
- `searchBooksByAuthor` の取得方法を変更
  - 使う API: `BooksBook/Search`（書籍のみ）
  - 検索条件: `author` パラメータ
  - 並び順: `sort: "-releaseDate"`（発売日の新しい順）
  - 効果: 上位30件が常に最新刊になる。予約中の本も含まれる。
- 著者名を比較する前に、半角・全角スペースを除去する（`normalizeAuthor`）
  - 例: 本棚の「東野圭吾」と楽天の「東野 圭吾」が一致する
- 楽天の商品データを `Book` に変換する処理が3箇所に重複していたため、`toBook` にまとめた

新刊ページ側（`app/(tabs)/New.tsx`）とプリロード側（`contexts/AuthContext.tsx`）は、どちらも `searchBooksByAuthor` を呼んでいるため変更していない。

## 未対応
- 途中で買うのをやめた本の除外（スキップ判定）
- 「2026年10月」のように日付の「日」がない `salesDate` の解釈
- プリロード時のレート制限（429エラー）対策
